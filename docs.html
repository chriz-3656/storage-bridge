Command Reference

Storage Bridge provides a powerful, multi-layered CLI designed for both beginners and automation scripts.

Stateful Navigation (Level 1)

The CLI natively tracks your active cloud provider and working directory, allowing you to interact with clouds just like a local filesystem.

cd

Change your active directory within the default provider.

storage-bridge cd /my/backups/folder

list / ls

List files in the current working directory.

storage-bridge list
storage-bridge list subfolder

mkdir

Create a new folder in the active cloud environment.

storage-bridge mkdir new-folder

upload / download

Seamlessly transfer files between your OS and the active cloud working directory.

storage-bridge upload local-file.txt
storage-bridge download cloud-file.txt ./desktop/

Advanced Execution (Level 2)

Power users can bypass the stateful working directory by explicitly defining provider:path arguments.

CommandDescriptionExample
putUpload explicitly.put ./file.txt s3:bucket/file.txt
getDownload explicitly.get s3:bucket/file.txt ./file.txt
rmRemove file entirely.rm drive:/secrets/keys.txt
moveRename or move natively.move drive:/a.txt drive:/b.txt
syncConcurrent directory sync.sync local:./docs s3:my-docs --workers 8

Provider Management

Dynamically configure new storage connections.

Adding Amazon S3 (or R2 / Spaces)

# Standard AWS S3
storage-bridge provider add my-s3 --type s3 --bucket my-bucket

# Cloudflare R2 via custom endpoint
storage-bridge provider add my-r2 --type s3 --bucket my-bucket --endpoint https://id.r2.cloudflarestorage.com

Adding a Union Load Balancer

Combine multiple upstream providers into one virtual endpoint.

storage-bridge provider add hybrid-cloud --type union --upstreams local,my-s3 --policy first
